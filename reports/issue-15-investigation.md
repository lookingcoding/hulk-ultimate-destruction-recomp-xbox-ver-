# Issue 15: jump and carried-object investigation

The reported mid-air stall and drop have not been reproduced or attributed to a specific gameplay function. No gameplay fix is proposed by this investigation.

`src/game/simulation.cpp` wraps the ordered world update (EU `sub_00088CD0`, USA `sub_00088C30`) containing actors, props, physics and post-collision work. The USA wrapper includes the same source. Commit 03e5829 runs that pipeline at 60 Hz using `SimulationClock`, rebuilding the guest arguments for each catch-up call. Commit 4391c0e bypasses this clock when `TimeDilated(elapsed, real_dt)` is true: the entire pipeline then runs once per rendered frame with variable elapsed time, and its fractional accumulator is reset. The detection compares guest elapsed against host wall time, so scheduling delays or mismatched sampling intervals could classify an ordinary frame as dilated; repeated switching also discards fractional accumulated time. These are timing risks, not proof that either caused the reported bug. Eliminating this path outright could regress issue 11's cinematic camera/animation fix.

The port source and patches do not identify a jump/gravity or held-object attachment implementation by name. Those paths are in recompiled guest code; the existing test `simulation_render_independence` exercises only the clock, not gameplay, collision, or attachment. No test of a model of those mechanics would establish that the actual game is fixed.

The worktree has no `assets` directory; the existing EU and USA XBEs are available in `D:\Projects\Active\Hulk Recompiled\assets`. The prescribed script creates a source-tree `generated` junction, and builds require source-tree assets. Creating additional files or junctions on C: is prohibited by the workstation rule unless separately authorized. The script's `cmake --preset release` also selects the shared release directory even if `$build` alone is changed; a safe isolated invocation must override the CMake binary directory as well. No build or ctest was run.

Next: reproduce the actual jump/drop with a representative save and frame-rate/time-scale telemetry; log state transitions and actor/prop transforms at the ordered world-update boundary and find the guest jump and carry functions. Distinguish normal-frame false dilation, true critical-move dilation, and state transitions before choosing a fix. Validate EU and USA, both input methods, 60/120/144 Hz and the burning-apartment rescue, and preserve the issue 11 cinematic behavior. Add a regression covering the identified real mechanism; the existing clock-only test cannot verify carried-object behavior.
