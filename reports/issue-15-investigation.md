# Issue 15: normal-speed simulation timing

The reported jump stall and dropped object have not been reproduced in the burning-apartment rescue. A related scheduler defect was reproduced and corrected; its connection to those symptoms is plausible, not established.

The issue 11 hook inferred slow motion from guest elapsed time versus host wall time. In an active USA-XBE/EU-data city run, `hulk-2_002.log` recorded 31 bypasses while the guest timer's Q16 scale was 65536 (normal speed). For example, after a 0.9388 s host stall, guest elapsed was clamped to 0.066666 s and the bypass executed one large world update instead of fixed ticks. Jitter also triggered the bypass. That ordered world update includes actors, props, physics and post-collision work; variable update sizes can affect its physics, but these measurements did not establish the float/drop mechanism.

`src/game/simulation.cpp` now reads the main guest timer from `[kApp]+0x58` and its 64-bit Q16 scale at `+0x38`, instead of comparing elapsed with host wall time. A missing app or timer keeps fixed-step scheduling. When the guest scale is below 65536 the issue 11 every-frame path remains, preserving camera and animation updates during genuine slow motion. EU and USA each use their own `kApp` address and the shared hook. The test-only `HULK_TEST_TIMESCALE` now sets the guest multiplier, so the guest timer scales future elapsed values itself; `HULK_TEST_NO_DILATION_FIX` retains the accumulator-only control. `HULK_TEST_TIMING_AUDIT` enables bounded scale, branch and timer logging. `tests/simulation.cpp` covers missing clocks, scale boundaries, full speed and a clamped hitch.

The same city replay after the change logged 100 normal-speed timing samples with zero false bypasses (`issue15-run-usa/logs/hulk-2_003.log`). Forced 0.1x runs in EU and USA logged scale 6554 and raw/game timer values of 66666/6667, demonstrating that the game clock itself scaled elapsed. At 144 fps the enabled slow path recorded up to about 720 updates per five seconds in both regions; the USA accumulator-only control recorded about 30 (`hulk-2_005.log`). EU logs: `issue15-run-eu/logs/hulk-2_001.log`; USA enabled: `issue15-run-usa/logs/hulk-2_004.log`. No errors were logged in these runs. The first forced-scale sample can precede the next timer update; subsequent samples show the scale applied.

The USA tests used the USA XBE with copied EU archives and an isolated `sound_en.rcf` copy named `sound_uk.rcf`, because a full USA disc's data was unavailable. The first attempt hit a disc-error screen with missing `sound_uk.rcf`. The successful replay was a city mission (`c03m03`), not the reported rescue challenge; input logs show replay events but do not prove successful pickup or attachment. Runs used freshly built hosts with prior v0.4.6 guest DLLs while the isolated generated DLLs were still compiling. A real critical move, full USA assets, player-held object and the reported jump/drop remain unverified.

The first four-job build and a later one-job build were deliberately stopped when concurrent workload caused severe responsiveness or memory pressure; incremental outputs were retained. The host build and full five-test CTest suite passed. Final full-build results are recorded separately by the implementation handoff.

Both logs contained zero error lines. The USA mixed-region and mission limitations above still apply.
